## 云侧放行后的连接

云安全组增加**入方向 TCP 6025**。如有额外的云 NAT/公网端口映射，本方案要求将公网 6025 转到实例 6025，随后由实例规则转到 SSH 22。不要在本方案中将云端公网 6025 直接转到实例 22：实例将无法区分该连接与原公网 22 入口，后面的 finalize 限制会将它一起拒绝。

```powershell
ssh -p 6025 root@36.133.88.94
```

登录账号、密码/密钥不变。必须核对上述主机指纹；不得通过跳过主机指纹检查来通过验收。当前部署电脑若使用其旧版原生 SSH，可追加 `-o KexAlgorithms=curve25519-sha256` 处理本机 KEX 兼容问题。

只有从外网建立了**独立、认证成功且指纹一致的 6025 新会话**后，才可在该新会话中执行：

```bash
sudo /opt/xiaolin/deployment/ssh-portmap.sh finalize
```

它仅拒绝经 `eth0` 新建的原始目标端口为 22 的 IPv4 连接，保留原有已建立会话、6025 映射以及服务器内 SSH 22。本次已在新入口认证成功后执行 finalize；云侧新的批准范围不包含 22。

## 状态与撤销

```bash
sudo systemctl status xiaolin-ssh-portmap.service
sudo /opt/xiaolin/deployment/ssh-portmap.sh status

# 撤销旧 22 入口的本机限制，保留 6025 映射。
sudo /opt/xiaolin/deployment/ssh-portmap.sh reopen-old

# 完全撤销本次映射和本次 SSH 过滤规则。
sudo systemctl disable --now xiaolin-ssh-portmap.service
```

撤销只操作带 `xiaolin-ssh-6025` 标识的规则，不清空 iptables、不修改其他服务端口。若云侧已经关闭 22，恢复旧入口还需要云侧同步放行。若重新加载其他防火墙规则，应通过已有会话重启本映射单元并再次核对新端口。

服务器文件：`/opt/xiaolin/deployment/ssh-portmap.sh`、`/opt/xiaolin/deployment/ssh-portmap-6025.mode`、`/etc/systemd/system/xiaolin-ssh-portmap.service`。
