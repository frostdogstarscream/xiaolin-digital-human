# 官方大小模型课程与当前部署对照

资料来源：本目录 `pages/Xg00w3hfNiDmxekZSzbcDs45nyc.md` 与原始官方课程包。核对日期：2026-11-03。

官方课程的主线是：主模型作为第一响应者，判断闲聊或工具任务；独立大模型在后台执行工具循环；任务结束后主模型根据结果生成最终回复。后台任务执行期间，主模型还负责补充要求、进度查询、取消、新任务确认和普通闲聊的分流。

本机当前仍是单模型模式：

| 项目 | 当前证据 |
| --- | --- |
| 主问答模型 | `deepseek-v4.1-flash`，OpenCode Go |
| `big_model_engine` | 空 |
| 独立大模型接口与密钥 | 未配置 |
| 主模型与 TTS | 已分离，语音仍为百炼实时 TTS |
| 模型工厂及后台任务管理器 | 源码具备，支持角色分工与后台执行 |
| 双模型实际启用 | 未启用；模式判断以 `big_model_engine` 是否配置为依据 |

课程包的第三节使用 `_call_planner_llm` 名称，并描述超过 80 字的额外核实策略。公开“升级日志”的 2026 年 08 月 07 周、Fay v4.8.1 条目明确记录：planner 更名为 judge、删除 80 字兜底核实、删除 kb_search 硬编码优先，以及未配置 `big_model_engine` 时新增同步工具循环的单模型模式。

本机实际源码对应入口是 `_call_judge_llm`，具有上述单模型分支。因此旧课程中的“超过 80 字自动转大模型核实”等描述不能直接视为当前运行规则。
